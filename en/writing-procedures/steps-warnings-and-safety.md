## Writing a step

[d360]: # 'table border="all" striped="true"'

| Do | Instead of |
| :--- | :--- |
| One action per step | Three actions joined by "and" |
| Start with the verb | "You should then proceed to…" |
| Say what you will see | Leaving them unsure it worked |
| Name the control exactly as it is labelled | A paraphrase that nearly matches |

[d360]: # "/table"

> [!IMPORTANT]
> **A step with two actions in it will have one of them skipped**
>
> Not by careless people — by everybody, eventually, because a numbered list reads as one action per
> number and that is how it is followed.

## Where the warning goes

[d360]: # 'callout kind="error"'

> **Before the step, never after it**
>
> A warning placed after the instruction is read after the action. This is the single most common and
> most consequential formatting mistake in procedural documentation.

[d360]: # "/callout"

## Choosing a callout

Document360 gives you eight kinds. Using all eight on one page is how a reader learns to skip them
all, so agree a small set and mean it.

[d360]: # "tabs"

<details>
<summary>What they are for</summary>

A callout breaks the reading flow on purpose. That is a budget: a page with six of them has spent it,
and the seventh is invisible.

</details>

<details>
<summary>A set that works</summary>

Three kinds, agreed across the project: one for danger to a person, one for damage or data loss, one
for everything else worth noticing. Map them to Document360's kinds once and write the mapping down.

</details>

<details>
<summary>How to tell it is going wrong</summary>

When somebody asks which callout to use and nobody can answer without opening another page, the set
is too large. When a reviewer changes a callout's kind as a matter of taste, it is too vague.

</details>

[d360]: # "/tabs"

> [!CAUTION]
> **Consistency across the project beats correctness on one page**
>
> A reader learns what your warning colours mean in the first ten pages. If page eleven uses them
> differently, you have not added nuance — you have removed the meaning from the first ten.

## Checking a procedure is followable

- [ ] Hand it to somebody who has not done the task and watch, without helping.
- [ ] Count the places they hesitate. Each one is a defect.
- [ ] Check every control name against the thing itself.
- [ ] Read the warnings in order and ask whether each arrives in time.

[d360]: # 'callout kind="success"'

> **Ten minutes of watching beats any review**
>
> A reviewer reads what the page says. An observer finds out what it fails to say, which is the
> category of defect no amount of reading catches.
